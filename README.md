# MLPT – מסחר תוך-יומי עם נפילה לסווינג, דרך IB Gateway

מערכת מסחר בזמן אמת למניות ארה"ב. כל יום נטענת רשימת מניות; המערכת אוספת נרות דקה,
מחפשת אות כניסה בשעה הראשונה של המסחר, ומנסה לגזור רווח תוך-יומי קטן. פוזיציה שלא
הגיעה ליעד התוך-יומי נשארת פתוחה ועוברת ליעדי הסווינג שלה.

> **סטטוס:** לוגיקת המסחר, הסימולטור והדשבורד נבדקו בבדיקות אוטומטיות (86 בדיקות).
> **המתאם ל-IBKR לא הורץ מול IB Gateway אמיתי** – הוא נכתב מול ה-API של `ib_async` ונבדק
> רק בבדיקות לוגיקה לא-מקוונות. חובה לעבור את [רשימת הבדיקות בחשבון Paper](#בדיקות-לפני-מסחר-אמיתי)
> לפני שמפעילים אותו על כסף אמיתי.

## איך זה עובד

```
רשימה יומית ──► WATCHING   איסוף נרות דקה (יומיים אחורה + זמן אמת)
                   │  אות MACD בחלון הכניסה (ברירת מחדל 09:30–10:30 ניו יורק)
                   ▼
               ENTERING   פקודת Limit במחיר האות + מרווח קטן; מבוטלת אם לא התמלאה תוך 30 שניות
                   ▼
               INTRADAY   TP תוך-יומי (פעיל גם לפני/אחרי המסחר) + SL   ← זוג OCA אצל IBKR
                   │  ├─ TP / SL ─────────────────────────────► CLOSED
                   │  └─ 20:00 ניו יורק, לא הושג היעד
                   ▼
               SWING      הפקודות מוחלפות ל-TP ו-SL של הסווינג (GTC)
                      └─ TP / SL / מקסימום ימי החזקה / סגירה ידנית ─► CLOSED
```

**סטופ נגרר במקום מכירה ביעד (אופציונלי):** בהגדרות, "סטופ נגרר אחרי הגעה ליעד %" (0 = כבוי). כשהוא פעיל,
אין פקודת TP בשלב התוך-יומי. כשהמחיר נוגע ביעד בשעות המסחר הרגילות, ה-SL מוחלף בפקודת סטופ נגרר (TRAIL)
אצל IBKR, שמתחילה באחוז שנקבע מתחת למחיר שהפעיל אותה ועולה עם המחיר. אם המחיר לא מגיע ליעד, ה-SL הרגיל
נשאר, וב-20:00 הפוזיציה עוברת לסווינג כרגיל (גם אם הסטופ הנגרר כבר הופעל ולא נסגר). שים לב: ההפעלה נעשית
על ידי המערכת, לכן אם היא לא רצה ברגע שהמחיר מגיע ליעד, הרווח לא ננעל – ה-SL ממשיך להגן. להשוואה:
`run.bat backtest --from <תאריך> --to <תאריך> --vary intraday_trail_pct=0,0.2` (ראה "סימולציה ו-Backtest").

כללים שנקבעו:

- אין אות בחלון הכניסה ← המניה לא נקנית, ולא עוברת ליום הבא. כל יום רשימה חדשה.
- כניסה אחת לכל היותר למניה ביום. מניה שכבר מוחזקת (סווינג מיום קודם) לא נקנית שוב.
- גודל פוזיציה = אחוז מהתיק, עד תקרה בדולרים. אם אין מספיק מזומן פנוי – מדלגים על העסקה.
- חשבון מזומן: כסף ממכירה של היום עוד לא נסלק, ולכן לא משמש לקניות נוספות באותו יום.
- פקודות ההגנה (TP + SL) יושבות אצל IBKR, כך שהפוזיציה מוגנת גם אם המערכת או ה-VPS נופלים.
- אחרי הפעלה מחדש המערכת מסתנכרנת מול הפקודות והפוזיציות בפועל ולא שולחת פקודות כפולות.

## התקנה (Windows VPS)

1. להתקין [Python 3.11 ומעלה](https://www.python.org/downloads/) (לסמן "Add python.exe to PATH").
2. להוריד את הפרויקט, להעתיק את `config.example.toml` ל-`config.toml` ולערוך.
3. ב-IB Gateway: ‏Configure ← Settings ← API ← Settings:
   - לבטל את הסימון **Read-Only API**.
   - Socket port: ‏`4002` ל-Paper, ‏`4001` לחשבון אמיתי (אותו מספר ב-`config.toml`).
   - Trusted IPs: ‏`127.0.0.1`.
   - מומלץ: Auto restart (במקום Auto logoff), כדי שה-Gateway יעלה לבד כל יום.
4. להריץ:

```bat
run.bat check          :: בדיקת חיבור, נתוני חשבון ונרות. לא שולח פקודות
run.bat check --order  :: בנוסף: שולח ומבטל פקודת מניה אחת רחוקה מהשוק (Paper בלבד)
run.bat                :: הפעלת המערכת
```

הדשבורד: <http://127.0.0.1:8080> (מתוך ה-VPS, דרך Remote Desktop).

בלינוקס: `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt && .venv/bin/python -m mlpt run`.

### דברים שכדאי לדעת על IB Gateway

- ה-Gateway מתאתחל פעם ביום ודורש אימות דו-שלבי בערך פעם בשבוע. המערכת מתחברת מחדש לבד.
- כניסה לאותו משתמש מ-TWS או מהאפליקציה מנתקת את נתוני השוק של ה-Gateway. למעקב בטלפון
  עדיף משתמש שני לאותו חשבון.
- לא לשנות את `client_id` כשיש פוזיציות פתוחות – הפקודות הפתוחות שייכות למספר הזה.
- פקודות שנשלחות ידנית ב-TWS לא מנוהלות על ידי המערכת והיא לא נוגעת בהן.

## הרשימה היומית

נטענת בלשונית "רשימה יומית" – קובץ CSV או הדבקה. רק `symbol` חובה; תא ריק = ברירת המחדל מההגדרות.

```csv
symbol,intraday_tp_pct,intraday_sl_pct,swing_tp_pct,swing_sl_pct,max_hold_days,position_pct,max_position_usd
AAPL,0.5,,6,4,5,10,
NVDA,0.7,3,8,5,,,3000
MSFT,,,,,,,
```

| עמודה | משמעות | אם ריק |
|---|---|---|
| `symbol` | סימול המניה | חובה |
| `intraday_tp_pct` | יעד רווח תוך-יומי, % ממחיר הכניסה | ברירת מחדל (0.5) |
| `intraday_sl_pct` | סטופ בשלב התוך-יומי, % | הסטופ של הסווינג |
| `swing_tp_pct` | יעד רווח בסווינג, % ממחיר הכניסה | ברירת מחדל |
| `swing_sl_pct` | סטופ בסווינג, % ממחיר הכניסה | ברירת מחדל |
| `max_hold_days` | מקסימום ימי מסחר, ואז יציאה 10 דקות לפני הסגירה | ללא הגבלה |
| `position_pct` | אחוז מהתיק לפוזיציה | ברירת מחדל |
| `max_position_usd` | תקרה בדולרים לפוזיציה | ברירת מחדל |

אפשר גם רשימת סימולים בלבד (`AAPL, MSFT, NVDA`). הרשימה נטענת לתאריך מסחר מסוים: עד סוף חלון
הכניסה ברירת המחדל היא היום, ואחריו – יום המסחר הבא. מיד עם הטעינה מתחיל איסוף הנרות.

## הדשבורד

- **סקירה** – פוזיציות פתוחות (שלב, רווח/הפסד, האם TP ו-SL פעילים, כפתור סגירה ידנית), רשימת היום ואירועים אחרונים.
- **גרפים** – נרות לכל מניה ותאריך, ממוצעים נעים, חלונית MACD, סימוני קנייה/מכירה וקווי כניסה / TP / SL.
  ברירת המחדל היא יום אחד בנרות דקה. ב"טווח" בוחרים עד 20 ימי מסחר וב"נר" גודל נר מדקה עד שעה, לצפייה
  בפוזיציית סווינג. כפתור "גרף" של פוזיציה או עסקה פותח אותה על כל תקופת ההחזקה שלה. בנרות גדולים
  מדקה, הממוצעים וה-MACD מחושבים על הנרות המוצגים; האסטרטגיה עצמה עובדת תמיד על נרות דקה.
  **קו מדד:** קו דק ומקווקו על גרף המחיר מראה את המדד שהמניה הכי קרובה אליו, מותאם למחיר המניה בנר הראשון
  של שעות המסחר בתצוגה – כלומר "איפה המניה הייתה אם הייתה זזה כמו המדד". הוא לא משפיע על קנה המידה של
  הנרות. המדד נבחר אוטומטית לפי המתאם של תשואות 5 דקות ב-5 ימי המסחר האחרונים, ואפשר לבחור אחר או "ללא"
  (הבחירה נשמרת לכל מניה בדפדפן). המדדים הם תעודות סל – SPY‏ (S&P 500), ‏QQQ‏ (Nasdaq 100), ‏DIA‏ (Dow Jones),
  ‏IWM‏ (Russell 2000) – שנאספות יחד עם מניות הרשימה; הרשימה ניתנת לשינוי בהגדרות.
- **רשימה יומית** – טעינה, בדיקת תקינות והסרת מניות.
- **היסטוריה** – עסקאות סגורות וסיכום: כמה נסגרו תוך-יומי וכמה בסווינג, רווח אחרי עמלות.
- **Backtest** – הרצת האסטרטגיה על נרות היסטוריים והשוואה בין הגדרות (ראה "סימולציה ו-Backtest").
- **הגדרות** – אחוז מהתיק לפוזיציה, תקרה, ברירות מחדל, חלונות זמן, פרמטרי האסטרטגיה.
- **לוג** – כל אות, פקודה, מילוי ואזהרה.
- כפתור **"השבת כניסות חדשות"** – עוצר קניות חדשות; פוזיציות פתוחות ממשיכות להיות מנוהלות.

1. ליצור בוט אצל [@BotFather](https://t.me/BotFather) ולהעתיק את ה-token ל-`config.toml`.
2. לשלוח לבוט הודעה כלשהי, ואז לפתוח `https://api.telegram.org/bot<TOKEN>/getUpdates` ולהעתיק את `chat.id`.
3. בלשונית "הגדרות": "שלח הודעת בדיקה לטלגרם".

נשלחות הודעות קצרות על קנייה, מכירה (כולל רווח, תוך-יומי/סווינג וסיבה), מעבר לסווינג, דילוג
בגלל מזומן, ניתוק מהברוקר ותקלות שדורשות טיפול.

## סימולציה ו-Backtest

```bat
run.bat demo                               :: דשבורד עם ברוקר מדומה ומחירים אקראיים – להכרת המערכת
```

**Backtest מהדשבורד:** לשונית "Backtest" – בוחרים טווח תאריכים ומקור לרשימה היומית, אפשר להוריד משם
נרות מ-IBKR, להריץ, ולהשוות בין כמה ערכים של הגדרה. התוצאות: טבלת השוואה, עקומת רווח מצטבר, ורשימת
העסקאות של כל הרצה. ההרצה מתבצעת בתהליך נפרד ועל מסד נתונים נפרד (`mlpt_backtest.db`), כך שהיא לא מעכבת
את המסחר ולא נוגעת בפוזיציות או בהגדרות.

**Backtest משורת הפקודה** – שני שלבים:

```bat
:: 1. הורדת נרות דקה היסטוריים מ-IBKR (IB Gateway צריך לרוץ; אפשר גם כשהמערכת עצמה רצה)
run.bat download --symbols AAPL,NVDA,MNDY --from 2026-10-01 --to 2026-11-12

:: 2. הרצת האסטרטגיה על הטווח
run.bat backtest --from 2026-10-01 --to 2026-11-12 --symbols AAPL,NVDA,MNDY
```

מאיפה מגיעה הרשימה היומית ב-backtest:

| אפשרות | משמעות |
|---|---|
| בלי פרמטר | הרשימות שנטענו למערכת בפועל באותם ימים |
| `--symbols A,B,C` | אותן מניות בכל יום בטווח |
| `--lists file.csv` | קובץ רשימות היסטוריות: עמודת `date` (YYYY-MM-DD) ועוד העמודות הרגילות של הרשימה |

הקרוב ביותר למציאות הוא `--lists` עם הרשימות האמיתיות שקיבלת בכל יום. `--symbols` בודק את האסטרטגיה גם
בימים שבהם המניה לא נבחרה, ולכן אומר פחות על התוצאה הצפויה.

**השוואה בין ערכים של הגדרה** – הרצה אחת לכל ערך וטבלת סיכום:

```bat
run.bat backtest --from 2026-10-01 --to 2026-11-12 --lists lists.csv --vary intraday_trail_pct=0,0.2,0.4
run.bat backtest --from 2026-10-01 --to 2026-11-12 --lists lists.csv --vary macd_min_depth_pct=0,0.1,0.2 --set intraday_tp_pct=0.7
```

`--set` משנה הגדרה לכל ההרצות, `--web` משאיר את הדשבורד פתוח על התוצאה (גרפים, עסקאות, "למה לא בוצעה
כניסה"), ו-`--source live` קורא נרות ממסד הנתונים של החשבון האמיתי. `download` בלי `--symbols` מוריד את
כל המניות שהופיעו ברשימות השמורות בטווח. `replay --date <תאריך>` נשאר להרצה חוזרת של יום בודד.

מגבלות שחשוב להכיר לפני שמסיקים מסקנות:

- הסימולטור ממלא פקודות לפי נרות דקה, בלי ספר פקודות ובלי החלקה. התוצאות אופטימיות ביחס למציאות,
  במיוחד עם יעדים וסטופים של עשיריות אחוז, שקטנים מטווח של נר אחד.
- הנרות ההיסטוריים הם מה ש-IBKR מחזיר לחשבון שלך; עם מנוי נתונים חלקי הם יהיו דלילים, כמו בזמן אמת.
- כמות ההיסטוריה ש-IBKR נותן בנרות דקה מוגבלת, והורדה של הרבה מניות וימים לוקחת זמן.
- פקודת `download` נכתבה מול ה-API של IBKR ולא הורצה מול Gateway אמיתי.

## אסטרטגיית הכניסה

ברירת המחדל היא `macd_cross`: קנייה בהיפוך הראשון אחרי ירידה, על נרות דקה, עם
MACD ‏11 / 26 / 9 (EMA, לפי מחיר סגירה – כמו ב-TradingView).

1. המחיר יורד בחלון הכניסה, וקו ה-MACD וקו ה-Signal יורדים שניהם מתחת לאפס.
2. קו ה-MACD חוצה כלפי מעלה את קו ה-Signal, כששניהם עדיין מתחת לאפס.
3. הנר שנסגר עם החיתוך הוא נר הכניסה.

שני תנאים מגדירים "ירידה משמעותית":

- **עומק:** השפל של קו ה-MACD בירידה של היום חייב להיות לפחות `macd_min_depth_pct` אחוז ממחיר
  המניה מתחת לאפס (ברירת מחדל 0.10). הערך באחוזים מהמחיר, כך שאותו מספר מתאים למניה של $20 ושל $600.
  0 מבטל את התנאי.
- **היום:** קו ה-MACD חייב לרדת היום מתחת לערך שבו סיים את יום המסחר הקודם. התאוששות מירידה
  של אתמול אינה אות.

החיתוך נבדק בסגירת כל נר דקה (ולא באמצע הנר), ולכן הכניסה מתבצעת עד דקה אחרי שהקווים נפגשים.
הנר נסגר לפי השעון, 4 שניות אחרי סוף הדקה, גם אם בדקה שאחריה אין עסקאות ו-IBKR עוד לא דיווח על נר חדש.

בלשונית "גרפים", מתחת לגרף, הטבלה **"למה בוצעה / לא בוצעה כניסה"** מריצה את האסטרטגיה מחדש על הנרות
השמורים של אותו יום ומציגה כל חיתוך עם התוצאה שלו: אות כניסה, או הכלל שחסם אותו (מעל קו האפס, עומק קטן
מהסף, מחוץ לחלון הכניסה). מתחתיה מופיע מה שהמערכת עשתה בפועל במניה באותו יום, כולל אות שהגיע באיחור
או דילוג בגלל מזומן.
החישוב נעשה על נרות שעות המסחר הרגילות, עם המשכיות מהיום הקודם; "לכלול נרות מסחר מורחב" מתאים
לגרף עם Extended Hours. בגרף בדשבורד יש חלונית MACD מתחת לנרות, עם סימון נקודת הקנייה.

אסטרטגיות חלופיות להשוואה ב-`replay`: ‏`ma_cross` (ממוצע מהיר חוצה מעל איטי) ו-`ma_trend`.
להוספת אסטרטגיה: לכתוב פונקציה ב-`mlpt/strategy.py` ולרשום אותה ב-`STRATEGIES`.

אם המערכת כבר הורצה לפני העדכון הזה, יש לבחור `macd_cross` בלשונית "הגדרות" – הגדרות שמורות לא מוחלפות.

## בדיקות לפני מסחר אמיתי

בחשבון Paper, עם `mode = "paper"`:

1. `run.bat check --order` מסתיים ב-`all good`, והמזומן שמוצג תואם למה שרואים ב-TWS.
2. נרות דקה מתעדכנים בגרף בזמן אמת בשעות המסחר.
3. כניסה: האות מופיע בלוג, פקודת הקנייה מתמלאת, ואצל IBKR נוצרות שתי פקודות מכירה (LMT + STP) באותה קבוצת OCA.
4. TP תוך-יומי: כשהוא מתמלא, פקודת ה-SL מתבטלת והפוזיציה מופיעה בהיסטוריה עם רווח ועמלה נכונים.
5. מעבר לסווינג: אחרי 20:00 ניו יורק הפקודות מוחלפות למחירי הסווינג.
6. הפעלה מחדש של המערכת כשיש פוזיציה פתוחה: אין פקודות כפולות.
7. הפעלה מחדש של IB Gateway: המערכת מתחברת מחדש והנרות ממשיכים.
8. סגירה ידנית מהדשבורד, בשעות המסחר ואחריהן.
9. התראות טלגרם מגיעות.

רק אחרי כמה ימי Paper תקינים: `mode = "live"`, ‏`port = 4001`, ולהתחיל עם תקרה נמוכה לפוזיציה.

## מגבלות וסיכונים

- **יחס סיכון/סיכוי:** יעד של 0.5% מול סטופ של כמה אחוזים דורש אחוז הצלחה גבוה מאוד, והמנצחות
  המהירות נמכרות מוקדם. כדאי לבדוק ב-`replay` על ימים אמיתיים.
- **עמלות:** ב-IBKR (תמחור קבוע) המינימום הוא כ-$1 לפקודה. בפוזיציה של $1,000 קנייה ומכירה הן כ-0.2% – חלק ניכר מיעד של 0.5%.
- **פערי לילה:** ה-SL פעיל רק בשעות המסחר הרגילות, ופתיחה בפער יכולה למלא אותו הרבה מתחת למחיר הסטופ.
- **מילוי חלקי / פקודות שבוטלו בצד IBKR:** המערכת מזהה ומחליפה את פקודות ההגנה, ואחרי 8 החלפות
  עוצרת את הניהול האוטומטי של הפוזיציה ושולחת התראה.
- **לוח החגים** מחושב לפי כללים. סגירה חריגה של הבורסה מוסיפים ב-`extra_holidays`.
- המערכת אינה ייעוץ השקעות. האחריות על הפעלתה ועל תוצאות המסחר היא של המפעיל.

## מבנה הקוד

| קובץ | תפקיד |
|---|---|
| `mlpt/engine.py` | מכונת המצבים: אותות, כניסות, פקודות הגנה, מעבר לסווינג, סנכרון |
| `mlpt/strategy.py` | אסטרטגיות הכניסה והממוצעים הנעים |
| `mlpt/broker/ib.py` | מתאם ל-IB Gateway (נרות, חשבון, פקודות) |
| `mlpt/broker/sim.py` | ברוקר מדומה ל-demo, ל-replay ולבדיקות |
| `mlpt/watchlist.py` | פענוח ובדיקת הרשימה היומית |
| `mlpt/market_calendar.py` | ימי מסחר, חגים וסגירות מוקדמות (שעון ניו יורק) |
| `mlpt/db.py` | SQLite: נרות, רשימות, פוזיציות, פקודות, מילויים, לוג |
| `mlpt/web/` | ה-API והדשבורד; `jobs.py` מריץ backtest והורדות כתהליך נפרד |
| `mlpt/notifier.py` | טלגרם |
| `tests/` | `pip install -r requirements-dev.txt && pytest` |

הנתונים נשמרים ב-`data/mlpt_<mode>.db` – קובץ נפרד ל-Paper ול-Live – והלוגים ב-`data/logs/`.
